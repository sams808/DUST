# FAQ / troubleshooting

**A row shows no point on either plot.**
Its formers denominator (D = weighted sum of checked "former" oxides,
usually Al2O3+B2O3) is 0 - division by zero, so R'/K' are undefined
and the row is silently skipped rather than crashing. Check the
Formulas / Oxides tab has at least one former oxide checked, and that
your row actually has a nonzero value in one of the checked columns.

**N4 shows blank/NaN for a row that clearly has data.**
The row's R' is >= RD3 (`K'+2`) - it's past the Dell/Du-Stebbins
model's valid range ("Beyond model validity" regime). This is
physically meaningful, not a bug: the model is defined for a specific
compositional range and doesn't extrapolate past full network
depolymerization. Check the Results tab's "NBO regime" column.

**Why don't the %NBO-species columns have values for the Lu et al. 2021 series?**
That model doesn't publish an NBO-Si/NBO-B breakdown - only N4. The
%NBO columns are always computed from the Dell/Du-Stebbins model. See
[MODELS_REFERENCE.md](MODELS_REFERENCE.md).

**How do I compare my measured N4 against a model's prediction?**
Add a `N4_measured` oxide... no - add it as a regular column isn't
supported (only recognized oxides + Sample/Label are table columns).
Instead: import/enter your compositions, export the Results CSV, and
join your measured N4 against the model columns there; or use "Color
points by" on the K' vs R' tab with a numeric column you've encoded
some other way. (If you frequently need a "measured value" column in
the table itself, that's a reasonable feature request - see the note
about extending `EXTRA_COLUMNS` in `gui/table.py`.)

**Which R' should I trust for my own glasses?**
Whichever matches how you're charge-balancing your network - that's
exactly why the formula is editable rather than fixed, and why any
oxide (not just a fixed alkali/alkaline-earth list) can be assigned as
a former or modifier with its own weight. See
[CUSTOMIZATION.md](CUSTOMIZATION.md#rk-formula-editor).

**Can I run this without installing anything permanently?**
Yes - `install.ps1` only installs normal pip packages into your
existing Python 3.11, no system changes beyond that. There's no
installer that writes to Program Files or the registry.

**The app window shows generic text instead of the logo/splash.**
The brand assets (`assets/dust_logo.png`, `assets/dust_splash.png`,
`assets/dust.ico`) are generated by `make_logo.py` and committed to
the repo, but if your `assets/` folder is missing or you've edited the
logo design, run `py -3.11 make_logo.py` (or re-run
`install.ps1`/`update.ps1`, which do this for you) to regenerate them.

**Something else is broken.**
Run `py -3.11 -m pytest tests/` first - if the model tests fail, the
calculations themselves are broken (please report it, that's the
scientific core). If they pass but the app crashes, run
`py -3.11 app.py` from a terminal (not the `.bat`) so you can see the
full Python traceback.
